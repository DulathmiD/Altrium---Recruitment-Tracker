# Story Implementation Table — Altrium HR Backend

Built from the actual Acceptance Criteria doc (`Acceptance criteria (4).docx`, US-01–US-50) against the real backend code, not from memory. Two things surfaced while building this that are worth flagging before you trust the doc set:

1. **The Product Backlog only goes to item 44, but the AC doc goes to US-50.** They were never reconciled — some AC stories (US-42, US-44, US-45 etc.) have no matching backlog row at all. (Now fixed in `docs/Product-Backlog.docx`, which reconciles all 45 real stories against the full US-01–US-50 numbering.)
2. **US-18 as written is not "numerical vs descriptive ratings"** — its actual body says "I want to edit submitted feedback for a specific applicant," which duplicates US-23 almost exactly. This confirms the earlier deletion call was right, not just a guess.
3. **US-20 is not just a numbering gap — it's a deleted feature.** The raw team backlog and `Manual_Test_Cases.docx` both still carry it: "As an Interviewer, I want to update candidate progression stages after each interview" (TCI-44/45/46, "Candidate progression updates"). It's absent from the AC doc because it was superseded by the US-19 redesign (HM's binding recommendation is now the only way a stage changes) — someone pulled it from the AC doc but never cleaned it out of the backlog/test-case docs. Fixed in the regenerated Manual Test Cases docs (collapsed to one row marked SUPERSEDED, kept only for traceability).
4. US-40 and US-41 don't exist in the doc at all (not a formatting artifact, checked) — no corresponding story anywhere, backlog or test cases.
5. **Doc-vs-build drift found during a full audit against `Manual_Test_Cases.docx`, the AC doc text, and the live regression suite:** US-02's account-deactivation message and every US-01 negative-login test case quote "Incorrect username or password" — the real, deliberate error text is the generic `"Invalid email or password"` (same message for wrong password *and* deactivated account, by design — avoids leaking account status). US-02 also requires a phone number for user creation; `User` has no such field. US-19's AC/test language ("recommendation... stage not changed") describes the old advisory model; the real one is binding. US-25's AC text says "department"; the real scoping (and its own paired test case) is per-vacancy. US-26's test cases assume an automatic 2-week timer; the real system is 100% manual (HR-triggered). US-31's fixed "7 recruitment stages" list no longer exists post-US-05-redesign (now 4 anchors + variable per-vacancy rounds). US-37's AC text says reports require a closed vacancy; the real endpoint (and its own test case) allows open-or-closed. US-48's test cases assume manual multi-candidate selection; the real build auto-picks the top 5 by score. Fixed in the regenerated Manual Test Cases docs; AC doc corrections tracked separately.
